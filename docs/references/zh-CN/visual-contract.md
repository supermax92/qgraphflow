# 图形表达约定

[English](../../../skills/q-flow/references/visual-contract.md) · [简体中文](visual-contract.md) · [Русский](../ru/visual-contract.md) · [Português](../pt/visual-contract.md) · [日本語](../ja/visual-contract.md) · [Deutsch](../de/visual-contract.md) · [Español](../es/visual-contract.md)

本文件用于编写图数据。Viewer 实现和交互检查见[开发指南](viewer-development.md#viewer-visual-and-interaction-contract)。

- 初始阅读视图就应能回答用户的问题。使用清晰主路径、真实组件／职责名称，以及动作、消息或数据含义明确的边标签。边界放在节点后面，标签避开分组标题。
- 用合法的 `business` 种类或 `core`／`business` 标签强调实际业务中心。Viewer 提供冷中性的 Slate 表面、Iris 核心／交互色、Cyan 数据色、Orange 决策／失败色。普通组件保持中性；不添加颜色字段，不臆造 `core` 种类。
- 颜色用于补充名称和记法。集合中同一模块复用完全一致的非空 `module`，让 Viewer 提供稳定清晰的整节点底色、轮廓、色条和普通边颜色。模块颜色不能取代形状、名称、关系符号或证据样式，作者不提供字面颜色值。除类型记法另有要求外，框架／推断边保留虚线。协议、多重性、守卫条件和来源锚点必须准确。
- 根据完整文字调整各个框和走线通道；整体等比例放大布局会在适应画布时抵消可读性收益。遵循[图数据格式](graph-schema.md#routing-and-spacing)中的尺寸、自动通道、端点净空和路由提示规则。先移动节点，再添加路由提示；路线不得进入任何节点内部。
- Viewer 在打开、重置、切图、进入全屏时适应整张图，整体缩放绘制内容；低缩放不能隐藏字段、成员、副标题或其他节点文字。使用缩放、平移和小地图查看细节。SVG / PNG 导出覆盖整张图，图数据必须保留完整内容。
- 根据请求领域自身的证据作图。预览模型、事实和源码路径只是示例。

## 各类型记法

阅读当前类型对应行；合法种类和必需字段见数据格式。

| 类型 | 构图与路由 |
| --- | --- |
| 架构 | 入口 → 核心职责 → 协作方；明确所有权／运行边界，分离跨层扇出和扇入。 |
| 流程 | 胶囊形起止、处理、菱形判断、输入输出、子流程；成功与替代分支使用独立通道。 |
| 时序 | 对齐参与者／角色、生命线、编号消息、虚线返回和 `alt`／`opt`／`loop` 框。自调用位于生命线外；多行标签避开相邻消息；异步回调不画成同步等待。 |
| ER | 实体头部、完整 PK/FK/UK 字段、两端基数；分离多条关系并预留符号空间。 |
| 部署 | 主机／集群／网络边界内的设备、节点、容器和制品；表达物理位置，跨容器标签保持清晰。 |
| 类 | 名称／构造型、属性、方法；继承三角、组合／聚合菱形、多重性分别留出空间。 |
| 状态 | 初始圆点、终止双圈、状态、选择和带守卫的迁移；分开失败／取消路径、平行迁移与自循环。 |
| 用例 | 角色、椭圆能力、系统边界；区分角色关联与有标记的 `include`／`extend`。 |
| 数据流 | 外部实体、处理、数据存储；每条有向流命名所传数据，分离共享生产者／消费者通道。 |

用户要求集合时，所有视图使用同一套已核实的领域词汇，按九类图的规范顺序排列，生成前校验完整集合。任一视图失败都会阻止整个集合交付。
