# 図の構成規約

[English](../../../skills/q-flow/references/visual-contract.md) · [简体中文](../zh-CN/visual-contract.md) · [Русский](../ru/visual-contract.md) · [Português](../pt/visual-contract.md) · [日本語](visual-contract.md) · [Deutsch](../de/visual-contract.md) · [Español](../es/visual-contract.md)

図データを書くための参照文書です。Viewer の実装と操作確認は[開発ガイド](viewer-development.md#viewer-visual-and-interaction-contract)を参照してください。

- 最初の表示で依頼された問いに答えられる構成にします。明確な主経路、実際のコンポーネント／責務名、動作・メッセージ・データ名の接続線を使います。境界はノードの背後に置き、ラベルをグループ見出しから離します。
- 実際の業務中心を合法な `business` 種別または `core`／`business` タグで強調します。Viewer は冷中性色の Slate、中心／操作の Iris、データの Cyan、判断／失敗の Orange を提供します。通常の要素は中性色にし、色フィールドや架空の `core` 種別を追加しません。
- 色は名前と記法の補助です。同じモジュールには全ビューで同じ空でない `module` を使い、ノード全体の色、輪郭、帯、通常の接続線色を安定させます。色で形・名前・関係記号・証拠スタイルを置き換えず、色値を直接指定しません。種類固有の記法を除き、フレームワーク／推論の線は破線を保ちます。プロトコル、多重度、ガード、出典アンカーを正確に保ちます。
- 全文に合わせて個々の枠と経路の間隔を調整します。全体の一律拡大は画面に収めた際に効果を失います。[データ形式](graph-schema.md#routing-and-spacing)の寸法、自動レーン、端点余白、経路ヒントに従い、ヒント追加より先にノードを移動します。経路はノード内部を通しません。
- Viewer は起動、リセット、図切り替え、全画面移行で図全体を表示します。全描画をまとめて拡大縮小し、縮小時もフィールド、メンバー、副題などを隠しません。詳細はズーム、パン、ミニマップで確認します。SVG / PNG は図全体を出力するため、データも全内容を保持します。
- 対象ドメイン自身の証拠で作図します。プレビューのモデル、事実、パスは例にすぎません。

## 種類別の記法

対象種類の行を参照してください。合法な種別と必須フィールドはデータ形式に記載しています。

| 種類 | 構成と経路 |
| --- | --- |
| アーキテクチャ | 入口 → 中心責務 → 協調先。所有／実行境界を明示し、層をまたぐ分岐と合流を分離。 |
| フロー | カプセル形の始終点、処理、判断の菱形、入出力、サブプロセス。成功と代替分岐に別の経路を確保。 |
| シーケンス | 整列した参加者／アクター、ライフライン、番号付きメッセージ、破線の戻り、`alt`／`opt`／`loop`。自己呼び出しはライフライン外に置き、複数行ラベルを隣のレーンから離す。非同期を同期待ちで表さない。 |
| ER | エンティティ見出しと完全な PK/FK/UK フィールド、両端の基数。複数の関係を分離し記号の余白を確保。 |
| 配置 | ホスト／クラスター／ネットワーク内の端末、ノード、コンテナー、成果物。物理的配置とコンテナー間ラベルを明瞭に。 |
| クラス | 名前／ステレオタイプ、属性、メソッド。継承の三角、合成／集約の菱形、多重度の余白を確保。 |
| 状態 | 初期の点、終端の二重丸、状態、選択、ガード付き遷移。失敗／取消、並行遷移、自己ループを分離。 |
| ユースケース | アクター、楕円の機能、システム境界。アクターの関連と `include`／`extend` を区別。 |
| データフロー | 外部実体、処理、データストア。有向フローにデータ名を付け、共通の生成側／消費側経路を分離。 |

集合を依頼されたら、全図で同じ検証済みドメイン語彙と9種類の標準順を使い、生成前に集合全体を検証します。1図でも不合格なら集合全体の引き渡しを止めます。
