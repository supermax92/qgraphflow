# Разработка и сопровождение Viewer

[English](../../../skills/q-flow/references/viewer-development.md) · [简体中文](../zh-CN/viewer-development.md) · [Русский](viewer-development.md) · [Português](../pt/viewer-development.md) · [日本語](../ja/viewer-development.md) · [Deutsch](../de/viewer-development.md) · [Español](../es/viewer-development.md)

Модули объединяются при сборке. После изменения исходников и сборки генератор встраивает все функции в автономный HTML. Загрузки плагинов и горячего подключения во время работы нет. Обычная генерация по-прежнему выдаёт только `index.html` и `graph.json`.

## Точки изменения

Пути относительно `assets/viewer/src/`:

| Цель | Точка входа | Ответственность |
| --- | --- | --- |
| Новый тип диаграммы | `diagrams/<type>.js`, `diagrams/registry.js` | Названия, порядок, допустимые виды, проверка, рисунок, контуры и правила связей |
| Тема, размер шрифта, интерлиньяж | `visual-style.js`, `radix-colors.js` | Общие для страницы/экспорта шкалы Radix, переменные, семантика, распознавание ядра и размеры |
| Форма и внутреннее размещение | `diagrams/<type>.js`; общие карточки в `diagrams/card.js` | Узлы страницы и SVG/PNG |
| Типографика SVG и примитивы | `diagrams/drawing.js` | `svgStyles()`, экранирование и примитивы; локальная область на странице, повторное использование в экспорте |
| Панель инструментов, сведения, адаптивная оболочка | `ViewerShell.jsx`, `styles.css` | Оболочка страницы, без второй HTML/CSS-реализации содержимого узлов |
| Свечение | `effects.css`, импорт из `main.jsx` после `styles.css` | Свечение роли, выбора и потока, тёмная виньетка; только палитра, удаляется одним файлом, отключается при снижении прозрачности/повышении контраста |
| Выбор и поиск | `features/useSelection.js`, `search.js` | Общий выбор, отклик, клавиатура, закрытие; ранжирование проверяется отдельно |
| Движение направленных рёбер | `features/useViewerController.js`, `DiagramCanvas.jsx` | Только направление, собственный переключатель и настройка уменьшения движения |
| Легенда | `ViewerShell.jsx`, `styles.css`; данные из `legend.js`, `visual-style.js` | Всплывающая легенда реальных категорий/линий, исходные символы, `nodeAppearance`, приоритет ядра |
| Панели и фокус | `features/usePanels.js` | Мобильная взаимоисключаемость, видимость, возврат фокуса; настройки панелей при смене вида сохраняются |
| Полный экран | `features/useFullscreen.js`, `features/useSelection.js` | Нативный API, ошибки и фокус; выбор не открывает внешний инспектор, Escape сначала завершает полный экран |
| Перетаскивание, обзор, блокировка, интервалы | `features/useGraphLayout.js`, `layout-nudge.js` | Текущие позиции и операции; D3 остаётся ограниченным сдвигом |
| Состояние представления | `features/usePresentation.js` | Проекция выбора/поиска на узлы и рёбра без второго владельца состояния |
| Скачивание | `features/download.js`, `export-svg.js` | Статический SVG по текущим координатам, PNG из этого SVG |
| Маршруты и проверка компоновки | `edge-routing.js`, `text-layout.js` | Общие пути, переносы и измерения страницы, экспорта и проверки |

`main.jsx` управляет загрузкой, сменой вида, темой и черновиками каждого вида. `features/useViewerController.js` объединяет функции и координирует сохранение/сброс; `ViewerShell.jsx` связывает UI. Сначала расширяйте существующий модуль; новый Hook нужен только для независимого состояния и жизненного цикла.

## Добавление типа диаграммы

1. Добавьте в `diagrams/` модуль с экспортом определения по умолчанию.
2. Импортируйте в `diagrams/registry.js` и включите в `DIAGRAMS`. Порядок регистрации задаёт меню коллекции; у одиночного графа меню нет.
3. Обновите `graph-schema.md`, `visual-contract.md` и инструкции автора в SKILL. Регистрация не обязательно требует менять структуру данных.
4. Соберите шаблон, создайте примеры, проверьте специальные узлы, связи и браузерные действия.

Повторно используйте правила и примитивы. Карточке, наследующей все правила архитектуры, достаточно `{ ...architecture, id: 'new-view', label: 'New view' }` и регистрации. Независимый тип обычно содержит:

```js
export default {
  id: 'new-view', label: 'New view',
  nodeKinds: ['component'], groupKinds: [], edgeKinds: ['call'],
  outline, // (node, x, y) => [[имя SVG-тега, геометрические атрибуты], ...]
  render,  // (node, x, y, fill, stroke, palette) => строка SVG
};
```

`render` рисует тело через `paint(outline(node, x, y), { fill, stroke })`, текст через `text` / `centeredTitle`. Код модуля доверенный, данные графа нет. Не вставляйте ввод в SVG-теги, атрибуты или текст без общего экранирования.

Необязательные хуки добавляйте по необходимости:

- `validateNode`, `validateEdge`: ограничения после общих; используйте переданные `requireString`, `validateStringArray` и другие. Каждая проверка создаёт новый набор номеров последовательности.
- `edgeLabel`, `undirected`, `dashedKinds`, `markers`: подписи, направление, штриховка нотации сверх доказательных стилей и существующие UML-маркеры.
- `cardLayout`, `compartments`, `sequence`, `cardinalities`, `endpointStub`, `selectionHeight`: правила карточек, секции ядра, линии жизни, концы ER и высота выбора.

Прямоугольные карточки используют готовые правила. Иные маршруты, точки соединения или UML-символы требуют общих расширений трассировки/рисования: регистрация не выводит неизвестную геометрию. Названия и классификацию `nodeAppearance` новых семантических видов добавляйте в `visual-style.js`. Сохраняйте уведомление Radix MIT из `radix-colors.js` в HTML и SVG.

## Ограничения общего рисования

`DiagramCanvas.jsx` и `export-svg.js` вызывают `renderNode()` из `node-svg.js`. Страница вставляет SVG в узлы React Flow; экспорт передаёт тому же рендереру смещение холста. `SelectionOutline.jsx` вызывает `renderSelection()` с тем же `outline`, меняя только штрих, прозрачность и тень.

Разделяйте позиции, содержимое и временное взаимодействие. Перетаскивание меняет координаты, выбор — ни координаты, ни форму. Экспорт получает только текущий граф и тему, без выбора/анимации. Границы, адаптация маркеров React Flow и органы управления остаются специфичными для среды; общее содержимое не означает одинаковые DOM страницы и SVG экспорта.

## Сборка и регрессия

Из каталога навыка с имеющимися зависимостями и браузерными средствами:

```bash
npm --prefix assets/viewer run build
node --test scripts/*.test.mjs
node scripts/generate-viewer.mjs /tmp/graph.json /tmp/new-viewer
node scripts/browser-interactions.mjs /tmp/new-viewer /tmp/new-viewer-check
```

Кнопка снизу слева переводит холст в нативный полный экран; панели и верхняя полоса остаются снаружи. После изменения размера один раз впишите граф, не меняя выбор/компоновку; при выходе сохраняйте обзор. Прицел означает вписывание, четыре угла — полный экран. Старый HTML перегенерируйте. При отсутствии поддержки обозначьте недоступность, ошибки запроса сообщайте в статусе холста.

Проверка использует реальные API. `QA_HEADED=1` открывает окно для полного экрана, Escape и фокуса:

```bash
QA_HEADED=1 QA_ONLY_EXTRAS=1 QA_EXTRAS=fullscreen,fullscreen-errors \
node scripts/browser-interactions.mjs /tmp/new-viewer /tmp/fullscreen-check
```

Скрипт проверяет каждый переданный тип в трёх размерах, светлой/тёмной теме и действиях. Для полной матрицы передайте коллекцию девяти типов. `QA_FIXTURE_DIR` добавляет специальные формы. Нужны соседние исходные модули; отдельно скопированный скрипт не автономен.

Сведения следуют выбору пользователя: `useSelection` владеет выбором, `useViewerController` выводит `inspectedNode`, быстрый просмотр и инспектор `ViewerShell` его используют. Нет автовоспроизведения, пошагового чтения или исполнения потока. Легенда — плавающая кнопка сверху слева; `.inspector-facts` остаётся последним разделом. `has-flow` в `DiagramCanvas` и `styles.css` управляют контрастом статического слоя при движении; выбор не должен заполнять промежутки движущихся штрихов.

```bash
QA_ONLY_EXTRAS=1 QA_EXTRAS=flow-contrast,inspector-sync \
node scripts/browser-interactions.mjs /tmp/new-viewer /tmp/new-viewer-sync-check
```

`diagram-modules.test.mjs` добавляет десятый тестовый тип во временной копии, меняет только её модуль/реестр и выполняет проверку, сборку, генерацию. В продукте остаётся девять типов. `MODULE_TEST_OUTPUT=/tmp/new-module-check` сохраняет копию; её `skills/q-flow/scripts/browser-interactions.mjs` проверяет `page/`. Копия сохраняет иерархию репозитория и корневые уведомления третьих сторон для проверки реальных зависимостей. Каталог не должен существовать.

После изменений пересоберите `assets/viewer-dist/index.html`. После установки проверьте реальный кэш и в новой сессии создайте проверочные результаты установленной версией. Старый автономный HTML содержит старый код и требует новой генерации.

## Названия и миграция QGraphFlow

| Идентификатор | Старое | Новое |
| --- | --- | --- |
| Продукт | CodeGraph Flow | QGraphFlow |
| ID плагина | `codegraph-flow` | `qgraphflow` |
| Каталог и вызов навыка | `create-interactive-codegraph` / `$create-interactive-codegraph` | `q-flow` / `$q-flow` |
| Имя навыка в интерфейсе | CodeGraph Flow｜交互式软件图 | Q flow |
| Закрытый пакет Viewer | `codegraph-flow-viewer` | `qgraphflow-viewer` |
| Каталог поставки по умолчанию | `docs/codegraph-flow/<scope>-<diagram-type>/` | `docs/qgraphflow/<scope>-<diagram-type>/` |

Пакет оставляет только новый вход навыка, без прежних псевдонимов. Область — девять видов программных диаграмм. Переименование MapSprig / QMindFlow сюда не входит.

Из корня используйте новые пути:

```bash
node skills/q-flow/scripts/validate-graph.mjs /tmp/graph.json
node skills/q-flow/scripts/generate-viewer.mjs /tmp/graph.json docs/qgraphflow/example-architecture
```

Каталог по умолчанию — соглашение поставки навыка; генератор требует явного назначения. Пользовательские старые каталоги, включая `docs/codegraph-flow/`, допустимы; замена требует `--force`. Старый `graph.json` переписывать не нужно: авторские старые названия в заголовках, источниках, узлах и доказательствах сохраняются. Старый HTML работает офлайн со встроенным брендом; обновляется генерацией из исходного JSON.

`CodeGraph`, `codegraph`, `@colbymchenry/codegraph`, `.codegraph/` принадлежат внешнему анализатору и не меняются; также сохраняются `__CODEGRAPH_FLOW_DATA__`, SVG-ID `codegraph-*` и префиксы временных тестовых каталогов.

## Визуальный и интерактивный контракт Viewer

Раздел для сопровождения и аудита взаимодействий. Для создания графов используйте [visual-contract.md](visual-contract.md).

### Общее представление

- Оболочка React Flow с главным холстом: он занимает окно под материальной панелью 52px с навигацией, меню коллекции, заголовком/подзаголовком, поиском с результатами, `···` для экспорта/сброса/блокировки/интервалов/оформления и переключателем инспектора. Нет шапки доски, подвала или блока бренда; продукт только в заголовке документа. Навигация/инспектор выдвигаются со своих краёв и изначально закрыты при любой ширине. Щелчок показывает рядом карточку (тип, имя, задача, источник, до четырёх тегов, сведения), не открывая инспектор. Главное визуальное внимание — диаграмме.
- По умолчанию следуйте `prefers-color-scheme` в реальном времени. `···` предлагает систему/светлую/тёмную тему; ручной выбор приоритетен в обе стороны. Тема сохраняет обзор, поиск, выбор, блокировку и панели.
- Палитра Radix Colors (MIT): Slate для холодных нейтральных поверхностей, Iris для ядра/действий, Cyan для данных, Orange для решений/сбоев. Сохраняйте права/лицензию в исходниках, HTML и SVG; без CDN во время работы или библиотеки компонентов.
- Реальное бизнес-ядро помечается существующим `business` или тегом `core`/`business` без учёта регистра. Iris 3/8/12 для заливки/границы/текста; в ER/классах только шапка, строки членов нейтральны. Ядро выше данных/предупреждений. Начальное/конечное состояние сохраняет точку/двойной круг; никаких нового `core` или полей цвета.
- Страница, узлы, MiniMap, точки инспектора, легенды и экспорт используют `visual-style.js`. Карточки Slate 2; светлый холст Slate 1 (`#fcfcfd`, почти белый), тот же первый шаг, что в тёмном. Для тёмного берите соответствующие тёмные шкалы.
- Цвета оболочки выводит `styles.css` через `color-mix`: четыре уровня `--label`, `--label-2/3/4`, разделитель `--sep`, заливки `--fill`, `--fill-2/3`, материалы `--material-thick`, `--material`, `--material-thin`. Тёмная тема переопределяет только основу/тени. Текст оболочки 11 / 12 / 13 / 15 / 20 px, SVG — `TYPOGRAPHY` / `--font-*`. У всех органов `:active` и общий `:focus-visible`; панели разделены линией .5px и одной тенью, `1px solid` только у знаков холста. Помимо `prefers-reduced-motion`, `prefers-reduced-transparency` делает материал непрозрачным `--panel` без размытия; `prefers-contrast: more` задаёт разделителям/вторичному тексту цвет подписи, плавающим слоям обводку 1px.

| Роль | Шкала / шаг Radix |
| --- | --- |
| Страница / обычная поверхность | Slate 1 / Slate 2 |
| Основной / вторичный текст | Slate 12 / Slate 11 |
| Ядро: заливка / граница / текст | Iris 3 / Iris 8 / Iris 12 |
| Действия / направленное движение | Iris 11 |
| Данные: заливка / граница / акцент | Cyan 3 / Cyan 8 / Cyan 11 |
| Предупреждение: заливка / граница / акцент | Orange 3 / Orange 8 / Orange 11 |
| Слабая граница / обычное ребро | Slate 6 / Slate 9 |

- В светлой теме без `module` остаётся ролевая заливка; с модулем вся карточка, контур и верхняя полоса получают его оттенок. Проверенное соответствие китайского примера: 渠道 `#6b7280`, 结算 `#5753d7`, 价格 `#8b5cf6`, 库存 `#0f8f83`, 风控 `#c26a17`, 支付 `#2474d2`, 订单 `#348052`, 履约 `#b14b7d`. Цвет не заменяет подписи, формы, кардинальности, линии и стереотипы; при выборе заливка сохраняется.
- Легенда включает только реальные категории/линии, с теми же приоритетом ядра, семантикой и текущей темой.
- Кнопка легенды сверху слева открывает поповер с переключателем потока при наличии направленных связей. Символы перед подписями сохраняют форму, цвета и сплошной/пунктирный стиль, обычный строчный текст переносится. При открытой навигации кнопка уходит вправо; панорамирование/масштаб не меняют её место/шрифт. Escape или внешний щелчок закрывают.
- Направленные связи по умолчанию имеют один мягкий движущийся штрих от источника к цели; ненаправленные неподвижны. Под ним сохраняется доказательная линия. Выбор не останавливает поток; его переключатель останавливает лишь фоновые штрихи, уменьшение движения — всё фоновое движение.
- Наведение/выбор используют контуры и тени, не масштабируя геометрию и не заменяя смысловые заливки/границы. Выбор даёт один общий отскок 760ms узлу и прямым рёбрам, затем статическое выделение; анимируются лишь толщина, непрозрачность и тень.
- `effects.css` — экранный слой после `styles.css`. В тёмном: `filter: drop-shadow` по `.node-surface` цветом модуля, иначе роли; акцент наведения/выбора; широкий ореол (узел 14px при .5, прямые рёбра 14px при .3, чтобы движущийся штрих сохранял ≥60% эталонного контраста), усиленный `.edge-flow` и верхняя радиальная виньетка 10%. В светлом — мягкая модульная тень и плоский холст. Только токены палитры, без карточного `box-shadow` (линии жизни `boxShadow === 'none'`), без влияния на экспорт. `prefers-reduced-transparency: reduce` или `prefers-contrast: more` выключают слой: фильтры `none`, ореолы/поток возвращаются к `styles.css`, виньетка удалена.
- Уменьшение движения отключает анимации связей/выбора и выполняет смену вида мгновенно.
- SVG/PNG используют текущую тему, нотацию, типографическую иерархию и общие ортогональные пути, без временного выбора/поиска. Подписи/символы внутри форм, описания SVG сохраняют полный авторский текст.

### Взаимодействие

- У одиночного графа нет меню; у коллекции канонический порядок `role=menu` / `menuitemradio`, отметка текущего и число связей. Смена хранит текст/позиции каждого графа, очищает поиск/старый выбор, вписывает целиком и применяет начальное ядро.
- Нет воспроизведения, шагов, тура чтения, текущего/пройденного шага. `playback` игнорируется; движение не показывает порядок исполнения.
- Изначально статически выделяется первое явное ядро и прямые рёбра, без импульса; при смене так же. Без ядра выбор пуст.
- Выбор показывает карточку и прямые входящие/исходящие рёбра; петлю один раз, без дальнейшего обхода и затемнения чужих связей. Текущий путь повторно используется без новых/увеличенных стрелок. Сохраните доказательный пунктир, ER-кардинальности и UML.
- Контур соответствует карточке, ромбу, параллелограмму, эллипсу, кругу состояния. У последовательности только шапка/актор, не вся линия жизни. После 760ms статично; другой узел заменяет весь набор, тот же повторяет один раз.
- Щелчок/начало перетаскивания выбирают и показывают карточку; каталог/поиск и Enter/Space открывают инспектор. Поток продолжается. Отклик/позиционирование один раз на действие; перетаскивание не центрирует и не уводит фокус.
- Щелчок по холсту, закрытие сведений или Escape очищают выбор. Поиск приглушает несовпавшие узлы без смены топологии.
- Инспектор сохраняет факты, поля, допустимость null, атрибуты, методы, источники и теги до изменения/очистки пользователем; не продвигается сам и не крадёт фокус.
- Поток различим при выборе: не заполняйте промежутки непрозрачной линией того же цвета. Проверяйте все прямые направленные рёбра, не только первое или `animationPlayState`. Уменьшение движения и переключатель приоритетны.
- Поиск игнорирует регистр и внешние пробелы. Порядок: точное имя, префикс, подстрока, подзаголовок/теги, факты/поля/атрибуты/методы; равные сохраняют исходный порядок, после сортировки берутся восемь.
- Компоновка изначально заблокирована; явное действие разрешает перетаскивание, скачивание использует текущие позиции.
- Упорядочивание интервалов после разблокировки — ограниченный D3-сдвиг: выбранный узел и соседи в один переход, без выбора все. Цель — 65px между прямоугольниками рядом с исходными местами; вложенные узлы внутри наименьшей границы, участники последовательности только горизонтально. Это не новая топология или полная автокомпоновка.
- При блокировке пункт серый с `aria-disabled="true"`, но реагирует на мышь/клавиатуру, чтобы статус попросил разблокировать. Название блокировки в одну строку, переключатель 32×20px внутри меню при всех ширинах. Не запускайте решатель и не разблокируйте автоматически. После попытки сообщайте локальную/общую область и число сдвинутых, отсутствие необходимости при чистой проверке или оставшиеся проблемы с советом ручной правки. Считайте ошибки и предупреждения даже при нулевом сдвиге.
- Если желаемые шапка/отступы не помещаются в границу при лимите движения 156px, оставьте исходное место и сообщите проблемы. Чужие узлы сохраняют точные координаты, включая дробные. Каждое действие обновляет сообщение и таймер 4.5s, даже при повторном тексте.
- Упорядочивание не меняет доказательства, подсказки маршрутов, группы, выбор, обзор, панели, тему. Сброс восстанавливает позиции `graph.json`, обзор чтения и стандартный поток, очищает поиск/выбор/старые сообщения; сохраняет тему, панели, блокировку и сообщает завершение.
- Панорамирование, масштаб, вписывание, сброс, SVG/PNG остаются доступны.
- Сохранение Graph JSON сохраняет текст/позиции всех видов в исходной форме графа/коллекции с метаданными, источниками и структурными полями. Нативный диалог при поддержке, иначе скачивание. Отмена/ошибка хранит правки; сброс касается только активного вида и следующего сохранения. Перезагрузка читает встроенное; перегенерируйте из сохранённого JSON. Регрессия включает смену туда/обратно, изоляцию сброса, JSON-скачивание и генерацию.
- Клавиатура и закрытие панелей сохраняют топологию; Backspace/Delete не удаляют узлы.
- Открытие/сброс/смена вписывают весь граф, панорамирование/масштаб/мини-карта дают детали. Границы как у экспорта: узлы, группы, внешние пути, подписи, ER-символы. Каталог/вписывание используют позиции после сдвигов; сброс — исходные.
- Каждое вписывание, включая полный экран, вычитает оболочку: сверху 52px+12px, снизу ряд управления, по сторонам открытая панель 304px+24px, закрытая 24px. `readingPadding()` в `useGraphLayout.js` читает `data-nav-open` / `data-drawer-open`; отступы — строки `px`, голые числа являются долями.
- Открытие навигации/инспектора/деталей карточки над выбранным узлом сдвигает обзор лишь до зазора 12px без масштабирования. Если узел не закрыт или ширина ≤700px, движения нет. `useReveal.js` явно вызывается из этих трёх действий, не из эффекта. Каталог/поиск продолжают центрировать.
- Программные перемещения используют `cubic-bezier(.32,.72,0,1)` за 320–420ms; панели — критически затухающую пружину (`visualDuration .36`, `bounce 0`). Уменьшение движения даёт обоим нулевую длительность, панель сразу в конечной точке.
- Масштабируется весь узел без скрытия подзаголовков, полей, атрибутов, методов, стереотипов, в том числе в полном экране. Центральный текст переносится внутри полезного прямоугольника, более узкого у ромбов/эллипсов/капсул/наклонных фигур. Измерение учитывает заглавные идентификаторы и широкую латиницу, заголовки границ оставляют место нотации фрагмента. `text-bounds` проверяет все типы, длинные поля/члены, границы, заглавные подписи рёбер, три масштаба; непустой текст с вычисленной нулевой непрозрачностью вызывает ошибку.
- Карточка пробует справа→слева→снизу→сверху: первое место внутри холста без перекрытия узлов. Если все подходящие стороны перекрывают соседей, минимальное перекрытие по реальной высоте. Раскрытие от узла (`is-flipped / is-below / is-above` задают `transform-origin`).
- Длинная карточка переносит/прокручивает текст в доступной высоте; закрытие/сведения доступны клавиатуре. В полном экране сведения сначала выходят из него, затем открывают/фокусируют существующий инспектор; при отказе карточка остаётся, ошибка объявляется.
- Открытая навигация сдвигает легенду/масштаб на 328px слева, инспектор — мини-карту на 328px справа (`.workspace.nav-open / .drawer-open`); при ≤700px они неподвижны.
- SVG/PNG включают всю диаграмму, а не только текущий обзор.

### Адаптивная компоновка

- Обе панели изначально закрыты на любой ширине, открываются наложением 304px от низа панели инструментов+12px до низа окна−12px, без затемняющей подложки; соседний холст доступен для движения. Escape закрывает сначала поповер, затем панель с фокусом (возвращая фокус переключателю), затем выбор. На промежуточной ширине не убирайте доступ к доказательствам.
- При ≤700px ширина панели окно−24px, взаимное исключение, мини-карта скрыта. Результат поиска открывает сведения и закрывает навигацию.
- Мобильные действия доступны, рядом виден холст, при 390px нет горизонтального переполнения. Инспектор сохраняет весь текст и вертикальную прокрутку.

### Представление доказательств

- Сначала идентичность, поля, атрибуты, методы, привязки, теги; затем факты того же узла отдельным последним разделом. С источником — доказательные факты, без — описание узла. Без фактов/узла раздел опускается, прокручивается вместе с содержимым.
- Прямой код, конфигурация, схема, тест, документ — сплошная линия, кроме требуемого нотацией пунктира, например возврат, зависимость, реализация.
- Поведение фреймворка и выводы остаются пунктирными, включая движение.
- Сведения называют это доказательством, не утверждают, что всякая привязка — исходный код.
- Длинные слова фактов, подзаголовков, полей, методов, символов и тегов переносятся; полный текст и только вертикальная прокрутка сохраняются.

### Приёмка в браузере

- Полная матрица только при изменении исходников Viewer, маршрутов, схемы или проверки: девять типов × 1440×900 / 1920×1080 / 390×844 × светлая/тёмная. Проверяйте стандартный поток, отсутствие воспроизведения, устойчивый выбор с движением, отдельный переключатель, динамическую легенду, панорамирование/масштаб, ранжированный поиск, связанное выделение без изменения геометрии/двойного импульса, полные сведения, блокировку/результат интервалов, сброс, SVG/PNG без временных эффектов, клавиатуру, уменьшение движения, переполнение. Нотация/ядро для каждого типа. Одиночный без меню, коллекция с вертикальным меню; при ≤700px панели изначально закрыты, доступны, взаимоисключающи.
- Откройте скачанные изображения: полные подписи, нотация, необрезанные границы, соответствие темы. Используйте установленный браузер, временные HTTP-серверы закрывайте в `finally`.
