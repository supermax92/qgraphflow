# Источники оснований и замена CodeGraph

[English](../../../skills/q-flow/references/evidence-sources.md) · [简体中文](../zh-CN/evidence-sources.md) · [Русский](evidence-sources.md) · [Português](../pt/evidence-sources.md) · [日本語](../ja/evidence-sources.md) · [Deutsch](../de/evidence-sources.md) · [Español](../es/evidence-sources.md)

CodeGraph — предпочтительный ускоритель анализа вызовов, но не обязательная зависимость.

## Предварительная проверка CodeGraph

Имеется в виду [`colbymchenry/codegraph`](https://github.com/colbymchenry/codegraph), доступный через локальную CLI или сервер MCP.

1. Проверить наличие `codegraph` в `PATH` и `.codegraph/` в целевом репозитории.
2. Если есть оба, выполнить `codegraph status`, затем один ограниченный запрос `codegraph explore "<question or symbols>"` перед прямым исследованием репозитория.
3. Уже настроенный инструмент CodeGraph MCP может выполнить тот же ограниченный запрос. Использовать реально доступные инструменты клиента, не предполагать специальные имена.
4. Если CLI, MCP или актуального индекса нет, сразу перейти к описанной ниже замене. Обычное рисование не требует установки/инициализации CodeGraph, определения версий npm или изменения конфигурации клиента.

## Необязательная настройка по запросу

1. Только по запросу или с разрешения пользователя определить точную стабильную версию через `npm view @colbymchenry/codegraph version`, проверить официальную инструкцию и поддерживаемые цели этой версии.
2. До установки определить клиент, команду и записи: исполняемый файл, настройки/инструкции клиента и индекс `.codegraph/`. Предпочитать настройки внутри проекта, если установщик это поддерживает. Не предполагать, что всем нужен `--target=codex`, и не выдумывать цели по именам клиентов.
3. Зафиксировать найденную версию пакета. Инициализировать только в разрешённом репозитории. При отсутствии интеграции использовать поддерживаемую отдельную CLI или прямое чтение кода; MCP не обязателен.
4. После настройки проверить `codegraph status` и использовать доступную CLI или MCP. При необходимости выполнить перезагрузку/перезапуск по правилам клиента. Если определение версии или установка не удались, сообщить об этом и продолжить прямой анализ, не пробуя другой установщик автоматически.

## Порядок замены

1. Начать с `rg --files`, затем сузить `rg` до объявлений, точек входа, вызывающего кода, реализаций, ключей конфигурации и тестов.
2. Прочитать весь относящийся к вопросу путь кода, сохранить привязки к файлам, строкам и символам.
3. Проверить модели сборки, упакованные артефакты, целевые тесты и настройки исполнения, если они меняют вывод.
4. Документацию фреймворка использовать только для поведения, которым он владеет; помечать `framework`, а не исходниками репозитория.
5. Неподтверждённые некритичные связи помечать `inference`. Непроверенные связи исключать из заявленного основного пути.

## Авторитетные источники по типу диаграммы

| Диаграмма | Предпочтительные основания без CodeGraph |
| --- | --- |
| Архитектура, последовательность, классы, поток данных | Точки входа, вызывающий код, интерфейсы, реализации, зависимости сборки, клиенты RPC/MQ и целевые тесты |
| Блок-схема, состояния, варианты использования | Согласованные требования и документы API, затем поведение контроллеров/сервисов и тесты; различия документации и реализации показывать отдельно |
| ER | Сначала DDL и миграции, затем сущности JPA, отображения ORM/MyBatis, ограничения и тесты репозитория |
| Развёртывание | Dockerfile, Compose, Kubernetes, Helm, настройки сервисов, сетевые политики и манифесты CI/CD |

Прямой анализ не гарантирует полного охвата рефлексии, внедрения зависимостей, сгенерированных прокси, маршрутизации во время исполнения, RPC и сообщений. Указать этот предел и различать `source`, `config`, `schema`, `test`, `document`, `framework` и `inference`.
