# Контракт JSON графа

[English](../../../skills/q-flow/references/graph-schema.md) · [简体中文](../zh-CN/graph-schema.md) · [Русский](graph-schema.md) · [Português](../pt/graph-schema.md) · [日本語](../ja/graph-schema.md) · [Deutsch](../de/graph-schema.md) · [Español](../es/graph-schema.md)

`scripts/generate-viewer.mjs` принимает один `Graph` или коллекцию. Старые графы без `meta.diagramType` остаются допустимыми и отображаются как `architecture`. Фрагменты показывают структуру; перед запуском добавьте узлы, на которые ссылаются рёбра, и проверьте компоновку.

```json
{
  "meta": {
    "title": "Required title",
    "diagramType": "architecture",
    "subtitle": "Optional supporting line",
    "sourceRef": "Branch, commit, document version, or evidence scope",
    "scope": "Verified evidence scope",
    "generatedAt": "ISO-8601 timestamp"
  },
  "groups": [
    {
      "id": "runtime-boundary",
      "label": "Consumer application JVM",
      "kind": "runtime",
      "position": { "x": 40, "y": 80 },
      "size": { "width": 1440, "height": 620 }
    }
  ],
  "nodes": [
    {
      "id": "jwt-decoder",
      "label": "NimbusJwtDecoder",
      "subtitle": "Verify and decode JWT",
      "module": "Identity",
      "kind": "security",
      "position": { "x": 720, "y": 220 },
      "size": { "width": 220, "height": 120 },
      "source": {
        "kind": "source",
        "file": "module/src/main/java/example/Config.java",
        "lineStart": 111,
        "lineEnd": 130,
        "symbol": "jwtDecoder"
      },
      "facts": ["Built from issuer-uri"],
      "tags": ["JWT", "Spring Security"]
    }
  ],
  "edges": [
    {
      "id": "decode-token",
      "source": "bearer-filter",
      "target": "jwt-decoder",
      "label": "decode and verify",
      "module": "Identity",
      "kind": "call",
      "evidence": "framework",
      "route": {
        "via": [{ "x": 640, "y": 180 }],
        "labelAt": { "x": 640, "y": 156 }
      }
    }
  ]
}
```

По умолчанию используйте один граф: у отдельной страницы нет меню типов. Для запрошенного просмотра нескольких диаграмм объедините 1–9 графов в `diagrams`. Каждый `meta.diagramType` должен быть уникален. Вертикальное меню панели всегда следует порядку `architecture`, `flowchart`, `sequence`, `er`, `deployment`, `class`, `state`, `usecase`, `dataflow`, независимо от порядка входных данных.

```json
{
  "diagrams": [
    { "meta": { "title": "System", "diagramType": "architecture", "sourceRef": "main" }, "nodes": [], "edges": [] },
    { "meta": { "title": "Request", "diagramType": "sequence", "sourceRef": "main" }, "nodes": [], "edges": [] }
  ]
}
```

Сокращённые графы показывают только оболочку. Каждый граф обязан соблюдать полный контракт и содержать узлы.

## Общие поля

- Обязательны `meta.title`, `meta.sourceRef`, непустой `nodes` и `edges`.
- `meta`, узлы, рёбра, группы и привязки к источникам — объекты; `nodes`, `edges` и необязательный `groups` — массивы объектов. Неверные контейнеры отклоняются до компоновки или генерации.
- Необязательные `meta.subtitle`, `meta.scope`, `subtitle` узла, `source.symbol` и `label` ребра — строки. Необязательные `module` узлов и рёбер — непустые строки: для одного бизнес-модуля используйте точно одинаковое значение во всей коллекции, не записывайте цвета. `facts`, `tags`, `attributes` и `methods` — массивы непустых строк. Правила общие для всех типов.
- Необязательный `fields` — массив объектов с непустыми строками `name` и `type`, необязательным `key` (`PK`, `FK`, `UK`) и необязательным логическим `nullable`. ER требует хотя бы одно поле; другие типы могут показывать поля в поиске и сведениях.
- `meta.diagramType`: `architecture`, `flowchart`, `sequence`, `er`, `deployment`, `class`, `state`, `usecase` или `dataflow`.
- `meta.locale`: необязательный язык интерфейса: `en`, `zh-CN` (по умолчанию), `ru`, `pt`, `ja`, `de` или `es`; `ko` и `fr` поддерживаются для существующих графов. Он управляет встроенным интерфейсом и подписями экспорта. Заголовки, подписи узлов, факты и отношения пишите отдельно на нужном языке; идентификаторы кода и стандартная нотация неизменны. У каждого графа коллекции свой язык.
- ID — уникальные непустые строки. Каждая конечная точка ребра ссылается на узел.
- Все узлы и группы имеют конечные неотрицательные значения `position` и `size`.
- `evidence` ребра: `source`, `code`, `config`, `schema`, `test`, `document`, `framework` или `inference`.
- `route` необязателен. `via` содержит промежуточные точки в координатах графа, а `labelAt` фиксирует центр подписи. Оба поля можно опустить, если автоматическая ортогональная трассировка понятна.
- Все координаты `route.via` и `route.labelAt` должны быть конечными и неотрицательными. Трассировщик вставляет прямоугольные повороты между точками и сохраняет первое/последнее соединение на текущих позициях узлов.
- Необязательный `source.kind` использует те же значения доказательств. `source.file` и `source.lineStart` задают точную привязку.
- С `--repo-root <directory>` проверка и генерация читают каждый `source.file` как текст UTF-8 по пути относительно репозитория и проверяют включительный диапазон строк. Абсолютные пути, переходы к родителю, каталоги, бинарные файлы и символические ссылки за пределы корня отклоняются. Повторные ссылки используют одно чтение файла. Без корня существующие привязки отмечаются в отчёте `skipped`, без привязок — `not-applicable`. Проверяется локальное рабочее дерево, а не соответствие ревизии `sourceRef`, разрешение символов или истинность утверждений.
- Для выделения бизнес-центра используйте существующий тип `business`, где он разрешён, либо `core`/`business` в `tags` без учёта регистра. Сохраняйте допустимый тип узла: `core` не является новым типом или полем схемы.
- Холодная нейтральная визуальная система — правило интерфейса. Цвет, типографика и выделение центра не требуют новых полей. Модель заказа и доставки из предпросмотра — пример, а не данные по умолчанию или источник доказательств.

Старые метаданные `playback` игнорируются. Автоматического и пошагового воспроизведения нет; движение направленных рёбер — отдельная визуальная подсказка, не порядок выполнения.

## Сохранение правок

Переключение типов сохраняет текст и позиции каждого графа в открытой странице. Сброс восстанавливает только исходные встроенные данные активного графа. **Сохранить Graph JSON** сохраняет всю коллекцию или исходную форму одиночного графа, включая правки других видов, метаданные и привязки. Поддерживаемые браузеры позволяют выбрать файл `.json`, остальные скачивают `graph.json`. Отмена или ошибка не удаляют правки.

Перезагрузка HTML снова использует встроенные данные. Сохраните JSON и сгенерируйте страницу в новом каталоге, чтобы позже открыть изменённую модель. Сохранение не отменяет проверку: новые подписи или позиции могут потребовать исправления компоновки перед генерацией. Браузер не перепроверяет источники; для подтверждённой исходниками поставки повторите обе команды CLI с `--repo-root`.

## Трассировка и интервалы

- Между прямоугольниками узлов оставляйте не менее 64 пикселей графа. Коридор с подписью должен вместить всю её расчётную ширину плюс 24 пикселя.
- Обычные карточки рассчитывайте на заголовки 20px, текст/поля/члены/рёбра 16px и вторичный текст 14px. Увеличивайте отдельные блоки и коридоры по содержимому; масштабирование всей схемы теряет эффект при вписывании. Это рекомендации автору, не новые минимумы проверки; старые компактные карточки и специальные символы совместимы. Начальный вид вписывает весь граф вокруг панели инструментов и открытых панелей с минимальным масштабом 0.08; явное вписывание использует тот же вид.
- Параллельные, расходящиеся и сходящиеся связи получают автоматические полосы по 24px. Возле конца можно разделять не более 12px пути; увеличенный просвет ER не разрешает объединять маршруты.
- Сторона узла должна вмещать полосы. При переполнении конечных точек увеличьте узел или задайте подсказки маршрута.
- Для заданных маршрутов без самопетли первая/последняя точка определяет сторону и проекцию точки на границу узла. Снаружи оставляйте прямой участок 28px для кардинальностей ER, 12px для остальных типов. Точки должны быть вне всех узлов, включая конечные.
- Самопетля по умолчанию занимает 48×32px снаружи правой границы. Используйте `route.via` или `route.labelAt`, только если это место занято.
- Проверка отклоняет наложение узлов, подписи поверх узлов/подписей, пути внутри любого узла (включая собственные концы), небезопасные петли и общие участки длиннее 12px. Сообщения последовательности сохраняют соединения с линиями жизни ниже заголовков. Тесные интервалы и пересечения дают предупреждения.
- Центры участников последовательности должны отстоять минимум на `max(160, estimated message width + 32)` пикселей.

## Нотация по типам

| `diagramType` | Узел `kind` | Группа `kind` | Ребро `kind` |
| --- | --- | --- | --- |
| `architecture` | `external`, `config`, `framework`, `security`, `service`, `business`, `data`, `failure`, `system`, `component`, `database` | `runtime`, `security`, `ownership`, `external` | `request`, `call`, `data`, `success`, `failure`, `framework`, `optional`, `depends` |
| `flowchart` | `start`, `end`, `process`, `decision`, `input`, `output`, `subprocess` | нет | `flow`, `yes`, `no`, `success`, `failure` |
| `sequence` | `actor`, `participant`, `external`, `service`, `database` | `alt`, `opt`, `loop` | `sync`, `async`, `return` |
| `er` | `entity` | нет | `relationship` |
| `deployment` | `device`, `node`, `container`, `artifact`, `service`, `database`, `external` | `host`, `network`, `cluster`, `namespace` | `deploy`, `network`, `depends` |
| `class` | `class`, `interface`, `abstract` | нет | `association`, `inheritance`, `implementation`, `composition`, `aggregation`, `dependency` |
| `state` | `initial`, `state`, `final`, `choice` | нет | `transition` |
| `usecase` | `actor`, `usecase` | `system` | `association`, `include`, `extend` |
| `dataflow` | `external`, `process`, `dataStore` | `ownership`, `external` | `data` |

### Последовательность

Рёбра требуют уникальный положительный целый `order`. Участники выравниваются сверху: заголовок 72px (108px для подписей акторов), высота для всех сообщений при существующем шаге 54px. Подписи показывают номер и могут переноситься со шрифтом 16px и высотой строки 24px; полные многострочные границы должны помещаться между сообщениями и под заголовками. Если нужно больше двух строк, увеличьте интервалы или переместите рамки. Группы `alt`, `opt`, `loop` охватывают нужный диапазон; отдельная асинхронная фаза не должна означать, что исходный синхронный запрос ещё ожидает.

```json
{ "id": "request", "source": "browser", "target": "api", "label": "POST /orders", "kind": "sync", "order": 1, "evidence": "source" }
```

### ER

Каждая сущность требует непустой `fields`. `key` может быть `PK`, `FK`, `UK`. Связь требует кардинальности обоих концов: `1`, `0..1`, `*`, `1..*`, `0..*`.

Заложите заголовок 72px, примерно 32px на поле и нижний отступ. Расширяйте столбцы ключа/имени/типа для имён 16px и типов и значков ключей 14px, особенно при длинных идентификаторах. Вне каждой сущности оставьте прямой участок 28px для символов. Значения кардинальностей JSON не меняются.

```json
{
  "id": "orders",
  "label": "orders",
  "kind": "entity",
  "fields": [
    { "name": "id", "type": "bigint", "key": "PK", "nullable": false },
    { "name": "user_id", "type": "bigint", "key": "FK", "nullable": false }
  ],
  "position": { "x": 80, "y": 120 },
  "size": { "width": 260, "height": 170 }
}
```

```json
{ "id": "user-orders", "source": "users", "target": "orders", "kind": "relationship", "sourceCardinality": "1", "targetCardinality": "0..*", "evidence": "schema" }
```

### Классы

Узлы могут содержать строковые массивы `attributes` и `methods`. Интерфейсы и абстрактные классы показывают стереотип. Заложите заголовок 68px, строки членов 28px со шрифтом 16px и отступы обоих отсеков; увеличьте ширину/высоту для имени, стереотипа и всех членов без обрезки или уменьшения. Наследование/реализация и композиция/агрегация используют свои треугольники и ромбы без изменения существующих типов рёбер.

### Состояния

Переходы могут содержать `guard` и `action`. Видимая подпись собирается как `label [guard] / action`.

### Привязки к источникам

Используйте `source` только для точного места в репозитории или предоставленном документе. Для внешних акторов и компонентов исполнения, принадлежащих фреймворку, опускайте его. `facts` должны быть короткими и атомарными; неопределённость отмечайте словами и типом доказательства.

В явно запрошенном концептуальном примере опишите бизнес-модель в `facts`, пометьте выведенные отношения `inference` и укажите эту область в метаданных. Не придумывайте пути и не переносите привязки предпросмотра в другой граф. Обычная генерация по-прежнему пишет ровно `index.html` и `graph.json`.
