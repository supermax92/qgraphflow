## 实施范围

右上角菜单以平台能力架构图、工程分层架构图、组件关系架构图、流程图、时序图、ER 图、部署图、类图、状态图、用例图、数据流图的顺序展示 11 个独立入口。重复同类视图增加标题；草稿仍按 `viewId` 隔离。JSON 继续使用九种语义类型，三种架构通过 `meta.architectureView` 区分，旧数据默认映射为组件关系架构图。

`layout-templates.js` 注册 11 种结构：能力分区、工程层次、组件聚类、流程主干与分支、参与者与消息行、实体矩阵、真实部署边界内的运行层、契约/实现与领域类并列、生命周期分支、系统外参与者、处理与存储分区。前两类沿用已有概览；时序保留专有编译器。其余模板按完整内容测量，复用路由、边界和编辑质量检查。显式方向交给固定方向的求解器，节点/关系/字段/方法/真实归属不因排版删减。

固定模块配色为蓝、青绿、淡紫、琥珀、灰绿，保留明暗主题和卡片底色开关。模块颜色跨视图稳定，时序调用/返回的八色配对独立保留。原有工具栏、搜索、详情、保存与导出 UI 保留；修复了窄屏打开导航时布局诊断浮层遮挡图例的问题。

主要改动入口：

- 技能入口、各类型参考页、README、插件元数据和 npm 文件清单：统一 11 类用户入口，保留九种底层数据类型。
- `examples/eleven-templates/collection.graph.json` 与 `eleven-templates.test.mjs`：无坐标的 11 模板回归输入；断言每类实际使用模板、事实完整及契约位于实现上方。

## 生成结果与紧凑度边界

所有产物位于 `output/demos/eleven-templates-implementation-20261007/`：

- `examples/index.html`：11 类模板示例，包含独立编写的虚构数据，不作为真实仓库实现结论。
- `jeepay/index.html`：原始 Jeepay 九个视图加用例/数据流两个明确标注的概念样例，共 101 个节点、124 条关系。逐字段比较确认原始九个视图的全部节点、边、分组及其内容保留。未重新验证 Jeepay 源码锚点或运行外部支付系统。
- 各目录中的 `graph.json` 和 SVG 来自真实生成器；PNG 来自实际浏览器导出，不使用手绘 demo 坐标。

11 类回归示例全部实际命中各自模板。复杂数据使用相同质量门槛：模板不能增加交叉、恶化宽高比例档位或超过现有候选 25% 的归一化面积/路由代价；不满足时保留质量更好的候选，`--verbose` 报告回退。

完整 Jeepay 的组件关系、部署、类、状态四图保留原有质量更好的布局。流程图面积从 2,824,400 降到 1,989,172（约减少 30%）；ER 为保留完整字段和清晰关系，面积约增加 3%；两类概览和时序结构按约定保留。没有声称每个复杂输入都缩小。具体数值见 `layout-comparison.json`。
